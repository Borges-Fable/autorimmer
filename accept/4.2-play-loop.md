# 4.2 Play-loop skill — acceptance (git-bug d2e1229)

The deliverable is behaviour text (`playbook/PLAY-LOOP.md`), so acceptance
has two halves: a bench run only the orchestrator can perform, and a
mechanical audit of that run's artifacts that anyone can perform after it.

## The bench run (orchestrator, on the box with the bench)

A scripted one-day session on a fixture colony, per the spec plus the
verification pass's amendments:

1. Stage the fixture (dev verbs, journaled as cheats; staging is the one
   sanctioned `dev:*` window). The fixture must be able to produce a
   **threat** inside the day — `dev:incident` a small raid during staging,
   or pick a save with one due — because the acceptance must exercise the
   emergency posture *and its exit*: draft (by exception) → fight →
   **undraft**, ending at zero drafted colonists.
2. `export RWA_RUN=<name>`, then run a session following
   `playbook/PLAY-LOOP.md` end to end: SESSION-START positions 1–10,
   colony-start section if the colony is fresh, turns until one full
   in-game day has elapsed, then the summary.
3. The session must contain at least one checklist-driven action — an
   `action` ledger line whose `note` names the act taken.

## The mechanical audit (anyone, afterwards)

    python accept/4.2-play-loop.py RUNS/<run> \
        --journal <protocol-root>/journal/<sid>.ndjson \
        --transcript transcripts/<run>

Checks: ledger schema + known item ids; daily coverage per day snapshot
(silent skip = missing line); ≥1 noted action; summary written; final digest
zero drafted / zero hostiles; advance envelopes within policy (cap 60,000,
`halt_on_error` never off, no two consecutive 0-tick advances); every
journaled `action`/`dev` verb covered by transcript ops at ≥ the journaled
count; zero `red_error`. Exit 0 iff no FAIL.

`--selftest` builds a pinned synthetic run in a temp dir, audits it (must
fully pass), then applies three mutations — a removed daily line, a drafted
colonist in the final digest, a doubled 0-tick advance — and requires each
to fail exactly its own check.

the auditor before it passes its own selftest there.

## The human gate (labelled as such, per the verification pass)

"Reviewed against the skill text for compliance" is not scriptable: Dorian
(or the orchestrator) reads the transcript against `PLAY-LOOP.md` — were
triggers run at their moments, was the drafted gate honoured before each
advance, was drill-down disciplined, was the dialog rule followed rather
than a 0-tick retry. The auditor shrinks this reading; it does not replace
it.
