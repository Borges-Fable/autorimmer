# Acceptance — 2.5 PNG render channel (git-bug `f7b6207`)

Written down by the orchestrator at the session-9 pause because these calls
existed only in a chat message, and repo convention is that acceptance lives
here. Authored by the worker; **not yet run**. Run in order on `autostart.rws`.

## What is already proven, and what is not

**Proven offline, no game involved:** `rwa/selftest.sh` §12, 23 checks —
render a rect twice off `fakebench` and `cmp`; render the saved dump offline
and `cmp` again. Bench render and offline replay come out byte-identical **in
separate processes**, which rules out in-process caching. That check exists
because a live colony moves between calls, so on a real bench "same dump twice
→ byte-identical PNG" could only ever be asserted, never demonstrated.

**NOT proven, and this is the load-bearing gap:** *the C# has never executed.*
The 147 selftest checks prove the renderer, the encoder and the client. They
prove nothing about `MapDumpVerbs.cs` or `CatalogDump.cs`, because what they
run against is `fakebench.synthetic_dump` — a Python reimplementation of the
shape the verb is *intended* to emit. **If the C# and that model diverge, the
selftest passes anyway and cannot see it.** The first live run is genuine first
execution.

Where a divergence would surface: `catalog-dump` returning a path, and the
first `map-dump` decoding without a `RenderError`. The renderer checks plane
length against the header and refuses a mismatch rather than drawing garbage,
so a divergence should announce itself rather than produce a plausible wrong
picture.

## The calls

```sh
rwa catalog-dump                 # ~3800 defs; writes <protocol root>/catalog.json

rwa landmark --json              # use base-center if present; else:
rwa pawns --json                 # take a colonist id -> "pawn:<id>" as --around

rwa render --around base-center --radius 25 --out /tmp/base-a.png --scale 16 \
           --save-dump /tmp/base.json --landmarks
rwa render --around base-center --radius 25 --out /tmp/base-b.png --scale 16 --landmarks
cmp /tmp/base-a.png /tmp/base-b.png          # must be silent

rwa render --dump /tmp/base.json --out /tmp/base-c.png --scale 16
# --landmarks is bench-only, so compare against a no-landmark bench render:
rwa render --around base-center --radius 25 --out /tmp/base-d.png --scale 16
cmp /tmp/base-c.png /tmp/base-d.png          # must be silent
```

## The legibility half — orchestrator only

Open `/tmp/base-a.png` **in a session that has seen nothing else** — no dump,
no `map-view`, no transcript — and ask the spec's three questions: how many
rooms, where are the doors, which room holds the stove. Rooms carry a tint and
a boundary stroke in that tint, doors a yellow outline, buildings a 2-char
catalog glyph (`ES` = electric stove), all three keyed in the legend strip.

`--scale 16` matters: below 12 the glyph labels are dropped rather than drawn
illegibly. A whole-map render at `--scale 3` is for a human's eyes, not an
agent's — it downsamples past readability.

If the colony has no stove the third question needs staging, and `0d9cbd7`
(world-fixture steps do not chain) is the hazard.

## Known risks, from the worker, before anyone runs this

- **`--whole-map` is the riskiest call here and was never measured.**
  `map-dump` reads `Room.Role` once per distinct room — cheap for a
  base-sized rect, but a whole map is every room on the map, each potentially
  triggering `UpdateRoomStatsAndRole()`, the lazy full room analysis
  `DigestVerb`'s header warns about. Idempotent and RNG-free, so nothing is
  corrupted, but it runs on the main thread at the safe point. If it hitches or
  trips the stall watchdog, `--layers terrain,things,zones,roof` drops the rooms
  plane and the cost with it. **Treat whole-map as optional and last.**
- **`ROOM_TINTS` has 12 entries and cycles.** A base with more than 12 enclosed
  rooms reuses colours, and since the per-room boundary stroke is drawn in each
  room's own tint, two adjacent rooms 12 apart in palette order share both. **If
  room-counting is the question that fails, this is the cause**, and the fix is a
  longer tint list, not a redesign.
- Legibility was verified by the worker on the synthetic fixture — by reading
  the PNG back as an image, which is how four defects were found and fixed (the
  legend running off the right edge, fog reading as empty space rather than
  unexplored ground, zone corner-ticks that looked like pawns, glyphs smudged
  inside a 12px swatch). But that fixture is two tidy rectangular rooms with
  five defs. A real base is neither.

## Budget

Measured, not estimated: at 250x250 the envelope is single-digit KB in the
realistic case and **~950KB worst case** (every cell differing in every plane),
1.1s render. An order of magnitude under per-cell JSON's ~4MB, but ~1MB is the
real ceiling.
