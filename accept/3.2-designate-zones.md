# Spec 3.2 acceptance — designation + zone verbs

Run by the ORCHESTRATOR against the live `_RimWorld-Agent` bench. The worker
wrote and compiled this and never launched the game.

Every step is one protocol envelope. Write it to `commands/<id>.json` and read
`results/<id>.json`, or use the `rwa` line beside it — they are the same call.
`rwa` needs `--...:json` for arrays and objects, because values are never split
on commas.

**Preconditions.** A loaded colony on `_RimWorld-Agent`, `devMode = True` (the
`dev:*` staging needs it; the player verbs do not), no force-pausing window up
(`rwa status`), and — for step group C only — a **growing season**: rice is sown
only when `GrowSeasonHereNow`, so run C in Spring or Summer. If C's `planted`
stays 0, check the season before suspecting the verb.

**Substitutions.** Steps marked *(discovery)* produce a value the next step
consumes. They are written as `<NAME>` and the step says exactly which field to
read. Nothing else in the script is variable.

**Standing assertions on every step**, checked once at the end (step F1):
`ok:true`, no `red_error` in the journal, and one `action` journal line per
mutating call.

## A — orientation and staging (discovery)

### A1. Where the colony is
```json
{"id":"a1","op":"pawns","args":{"filter":"colonist"}}
```
```
rwa pawns --filter colonist
```
Read `data.list[0].id` -> **`<PAWN>`** and `data.list[0].at` -> **`<HOME>`**
(an `[x,z]` pair; write it to `rwa` as the string `"x,z"`).

### A2. Make the working ground observable
```json
{"id":"a2","op":"dev:unfog","args":{"around":"<HOME>","radius":40}}
```
```
rwa dev:unfog --around <HOME> --radius 40
```
Expect `ok:true`, `data.dev.cheat:true`, `data.dev.fog_exempt:true`,
`data.dev.journal_seq > 0`. `cells_cleared` may legitimately be 0 if the area
was already explored.

### A3. A clear 6x6 block near home (discovery)
```json
{"id":"a3","op":"find-rect","args":{"w":6,"h":6,"near":"<HOME>","max":3,"require":["buildable"]}}
```
```
rwa find-rect --w 6 --h 6 --near <HOME> --max 3 --require buildable
```
Read `data.candidates[0].at` -> **`<CLEAR>`** = `[x,z]`. The rect
`[<CLEAR>.x, <CLEAR>.z, 6, 6]` is **`<CLEARRECT>`** and is buildable, unfogged
and edifice-free — i.e. it holds no mineable rock, which is what step E1 needs.

### A4. Trees near home (discovery)
```json
{"id":"a4","op":"things","args":{"category":"plants","in":"rect","rect":[0,0,1,1],"detail":true}}
```
Do **not** run A4 as written — it is a template. Run instead:
```
rwa map-view --around <HOME> --radius 20 --layers terrain --layers things
```
and read the grid: `T` is a tree, `,` is fertile ground, `.` is ordinary
ground, `%` is natural rock, `?` is still fogged. Pick

* **`<TREERECT>`** — an `[x,z,w,h]` covering at least 4 `T` cells, and
* **`<SOILRECT>`** — a 5x5 of `,` (or `.`) with no `T` and no `#`/`%`,

both inside the radius-40 unfogged disc from A2. If the biome has no `T`
within 20 cells, widen with `--radius 30`; a treeless map cannot satisfy
acceptance bullet 1 and the orchestrator should say so rather than improvise.

## B — bullet 1: chop-all-in-rect, and pawns actually take the jobs

### B1. Dry run first — the gate, with nothing mutated
```json
{"id":"b1","op":"designate","args":{"type":"chop","rect":"<TREERECT>","dry_run":true}}
```
```
rwa designate --type chop --rect:json '<TREERECT>' --dry_run
```
Expect exactly:
- `data.designator` = `"Designator_PlantsHarvestWood"`
- `data.gate` = `"RimWorld/Designator_PlantsHarvestWood.CanDesignateThing"`
- `data.designation` = `"HarvestPlant"`
- `data.accepted` >= 4 (one per mature tree in the rect)
- `data.dry_run` = `true`
- `data.designations_before` == `data.designations_now` — **nothing changed**
- `data.action.journal_seq` = `null`, `data.action.provenance` =
  `"not applicable — dry_run mutated nothing"`
- every non-tree cell appears in `data.rejects` with `why:"not-designatable"`
  and `reason:"Must designate wood-yielding, sufficiently-grown plants."`
  (an empty cell) — the game's own string, verbatim.

### B2. The real call — ONE call, N cells
```json
{"id":"b2","op":"designate","args":{"type":"chop","rect":"<TREERECT>"}}
```
```
rwa designate --type chop --rect:json '<TREERECT>'
```
Expect:
- `data.accepted` = B1's `data.accepted` (same gate, same answer)
- `data.designations_now` = `data.designations_before + data.accepted`
- `data.crop.rows` — the echo — contains `*` at the accepted cells
  (`crop.legend["*"]` mentions `HarvestPlant`)
- `data.action.journal_seq` > 0

**This is the plural test.** One envelope, N trees. Record
`data.action.journal_seq` -> **`<SEQ_B2>`**.

### B3. The journal carries the provenance
```json
{"id":"b3","op":"journal","args":{"since_seq":<SEQ_B2 - 1>,"types":["action"],"limit":5}}
```
```
rwa journal --since <SEQ_B2 minus 1> --type action --limit 5
```
Expect one event with `seq` = `<SEQ_B2>`, `type` = `"action"`, and payload
`verb:"designate"`, `step:"chop"`, `target` naming the cell count,
`counts.accepted` matching B2, `designation:"HarvestPlant"`.
**It must NOT carry `cheat` or `fog_exempt`** — an `action` is not a cheat.

### B4. Let the colony work
```json
{"id":"b4","op":"advance","args":{"ticks":60000,"max_tps":600}}
```
```
rwa advance --ticks 60000 --max_tps 600
```
Expect `data.reason` = `"ticks"` (any of `letter`/`alert`/`threat` is a normal
colony interruption — re-issue until 60000 ticks have run in total). If
`data.reason` = `"dialog"`, stop: something opened a force-pausing window and
the run is invalid until it is closed.

### B5. Wood exists and the designations are consumed
```json
{"id":"b5","op":"things","args":{"def":"WoodLog"}}
```
```
rwa things --def WoodLog
```
Expect a `WoodLog` rollup whose `count` is greater than before B4 — trees were
felled and the logs hauled. Then:
```json
{"id":"b5b","op":"designate","args":{"type":"chop","rect":"<TREERECT>","dry_run":true}}
```
Expect `data.designations_now` **lower than B2's** — the pawns took the jobs
off the designation list. That is the bullet: *jobs actually taken from the
designations.*

## C — bullet 2: a rice growing zone, and a meds-only stockpile

### C1. Growing zone refuses without a plant (the doctrine gate)
```json
{"id":"c1","op":"zone","args":{"op":"add","kind":"growing","rect":"<SOILRECT>"}}
```
```
rwa zone --op add --kind growing --rect:json '<SOILRECT>'
```
Expect `ok:false`, `error.code` = `"bad-args"`, and `error.detail` beginning
`zone add growing needs 'plant'`. **Nothing is created.** Confirm with
`rwa zones --kind growing` that the zone count is unchanged.

### C2. Rice, for real
```json
{"id":"c2","op":"zone","args":{"op":"add","kind":"growing","rect":"<SOILRECT>","plant":"Plant_Rice","label":"Rice 3.2"}}
```
```
rwa zone --op add --kind growing --rect:json '<SOILRECT>' --plant Plant_Rice --label "Rice 3.2"
```
Expect:
- `data.gate` = `"RimWorld/Designator_ZoneAdd_Growing.CanDesignateCell (-> Designator_ZoneAdd.IsZoneableCell)"`
- `data.accepted` = 25 (a clean 5x5) — any cell rejected `not-zoneable-or-infertile`
  means `<SOILRECT>` included poor soil; re-pick and re-run
- `data.zones_touched` = 1, `data.zones[0].plant` = `"Plant_Rice"`,
  `plant_configured:true`, `plant_source:"backing-field"`,
  `allow_sow:true`, `allow_cut:true`
- `data.action.journal_seq` > 0

Read `data.zones[0].id` -> **`<RICE>`**.

`plant_source:"backing-field"` is the proof that the read did **not** go
through `Zone_Growing.PlantDefToGrow`, whose getter scribes a default.

### C3. A meds-only stockpile
```json
{"id":"c3","op":"zone","args":{"op":"add","kind":"stockpile","rect":"<CLEARRECT>","filter":"meds","priority":"Preferred","label":"Meds 3.2"}}
```
```
rwa zone --op add --kind stockpile --rect:json '<CLEARRECT>' --filter meds --priority Preferred --label "Meds 3.2"
```
Expect:
- `data.accepted` = 36 (6x6)
- `data.zones[0].priority` = `"Preferred"`
- `data.zones[0].filter.defs` lists only medicine defs
  (`MedicineHerbal`, `MedicineIndustrial`, `MedicineUltratech` on a vanilla
  bench) — the whole-filter replacement, not a patch
- `data.action.journal_seq` > 0

Read `data.zones[0].id` -> **`<MEDS>`**.

### C4. Priority `Unstored` is refused, as the storage tab refuses it
```json
{"id":"c4","op":"zone","args":{"op":"edit","id":<MEDS>,"priority":"Unstored"}}
```
Expect `ok:false`, `bad-args`, detail naming
`RimWorld/ITab_Storage.FillTab skips it`.

### C5. Stage two piles: meds and something the filter must refuse
```json
{"id":"c5a","op":"dev:spawn-thing","args":{"def":"MedicineHerbal","count":20,"pos":"<HOME>"}}
{"id":"c5b","op":"dev:spawn-thing","args":{"def":"Steel","count":75,"pos":"<HOME>"}}
```
```
rwa dev:spawn-thing --def MedicineHerbal --count 20 --pos <HOME>
rwa dev:spawn-thing --def Steel --count 75 --pos <HOME>
```
Both `ok:true` with `data.dev.journal_seq > 0` and `data.placed` equal to the
requested count. Record the medicine's `data.spawned[0].id` if you want the
tighter assertion in C7.

### C6. Run the colony
```json
{"id":"c6","op":"advance","args":{"ticks":120000,"max_tps":600}}
```
```
rwa advance --ticks 120000 --max_tps 600
```
Two in-game days. Re-issue if it halts early on a letter or alert.

### C7. The stockpile received EXACTLY meds
```json
{"id":"c7","op":"things","args":{"in":"stockpile:<MEDS>","category":"all","detail":true}}
```
```
rwa things --in stockpile:<MEDS> --category all --detail true
```
Expect every entry's `def` to be a medicine def. **Steel must not appear.**
`data.query.scope.label` = `"Meds 3.2"` confirms you scoped the right zone.

### C8. The rice was sown and is growing
```json
{"id":"c8","op":"zones","args":{"kind":"growing"}}
```
```
rwa zones --kind growing
```
Find the entry with `id` = `<RICE>`. Expect:
- `plant` = `"Plant_Rice"`, `plant_configured` = `true`
- `planted` > 0 — colonists sowed it
- `growth_avg_pct` > 0 and rising across a repeat of C6+C8
- `wrong_plant` = 0

If `planted` is 0 after two days: check the season (rice is sown only in the
growing season) and that at least one colonist has Growing enabled. Neither is
this verb's doing — `zone edit` reports `allow_sow` so you can rule it out.

### C9. Shape it after the fact
```json
{"id":"c9","op":"zone","args":{"op":"edit","id":<RICE>,"allow_sow":false}}
```
```
rwa zone --op edit --id <RICE> --allow_sow:bool false
```
Expect `data.changed` = `[{"field":"allow_sow","value":false}]` and
`data.zones[0].allow_sow` = `false`. Set it back with `--allow_sow` (bare flag
= true) before continuing.

## D — the rest of the plural surface

### D1. forbid over a rect, then unforbid over a filter
```json
{"id":"d1a","op":"forbid","args":{"rect":"<CLEARRECT>"}}
{"id":"d1b","op":"unforbid","args":{"filter":{"category":"meds","rect":"<CLEARRECT>"}}}
```
```
rwa forbid --rect:json '<CLEARRECT>'
rwa unforbid --filter:json '{"category":"meds","rect":<CLEARRECT>}'
```
D1a: `data.designator` = `"Designator_Forbid"`, `accepted` = the number of
cells holding a forbiddable item; every empty cell rejects with
`reason:"Must designate unforbidden items."`. D1b: `target_scope.kind` =
`"filter"`, `target_scope.source` = `"group:Medicine"`, and `accepted` equals
the number of medicine stacks in the rect. Both carry an `action.journal_seq`.

### D2. flick echoes the designation, never the state
Pick a player-faction flickable — any powered building. `<FLICKID>` from
`rwa things --category buildings --detail true` (anything with a power comp;
a Standing Lamp or Battery from the starting kit will do).
```json
{"id":"d2","op":"flick","args":{"things":[<FLICKID>],"on":false}}
```
```
rwa flick --things:json '[<FLICKID>]' --on:bool false
```
Expect, IMMEDIATELY (no advance):
- `data.things[0].wants_on` = `false`
- `data.things[0].switch_is_on` = **`true`** — unchanged, because no colonist
  has walked over yet
- `data.things[0].flick_designated` = `true`
- `data.flick_designations_now` >= 1
- `data.note` names JobDriver_Flick

Then `rwa advance --ticks 20000 --max_tps 600` and re-run `flick` with
`dry_run:true`: `switch_is_on` is now `false` and `flick_designated` is
`false`. **A verb that had reported "power off" at D2 would have been lying**;
this is the contract the dispatch comment asked for.

### D3. area home, and an allowed area
```json
{"id":"d3a","op":"area","args":{"kind":"home","op":"add","rect":"<CLEARRECT>"}}
{"id":"d3b","op":"area","args":{"kind":"allowed","op":"create","name":"Test 3.2"}}
{"id":"d3c","op":"area","args":{"kind":"allowed","op":"add","id":<AREA>,"rect":"<CLEARRECT>"}}
```

```
rwa area --kind home --op add --rect:json '<CLEARRECT>'
rwa area --kind allowed --op create --name "Test 3.2"
rwa area --kind allowed --op add --id <AREA> --rect:json '<CLEARRECT>'
```
D3a: `gate` = `"RimWorld/Designator_AreaHome.CanDesignateCell"`, `cells_now` >
`cells_before`; cells already in the home area reject with
`why:"not-designatable"`. D3b: read `data.id` -> `<AREA>`;
`allowed_areas_now` increments; the note says the area is empty and that pawn
assignment is 3.4's verb. D3c: `cells_now` = 36.

Then confirm the rename gate:
```json
{"id":"d3d","op":"area","args":{"kind":"allowed","op":"rename","id":<AREA>,"name":"Home"}}
```
Expect `ok:false`, `bad-args`, detail
`area name 'Home' is already in use (Verse/Dialog_RenameArea.NameIsValid)`.

Clean up with `rwa area --kind allowed --op delete --id <AREA>`.

### D4. `remove` on a roof area is refused with the right instruction
```json
{"id":"d4","op":"area","args":{"kind":"no-roof","op":"remove","rect":"<CLEARRECT>"}}
```
Expect `ok:false`, `bad-args`, detail naming
`RimWorld/Designator_AreaIgnoreRoof` and `kind:"ignore-roof" op:"add"`.

## E — bullet 3: rejects report REAL reasons

Each of these is one call whose whole point is the rejection. Every `reason`
below is the game's own translated string, taken from
`Core/Languages/English/Keyed`.

### E1. mine on non-mineable
```json
{"id":"e1","op":"designate","args":{"type":"mine","rect":"<CLEARRECT>"}}
```
```
rwa designate --type mine --rect:json '<CLEARRECT>'
```
Expect `data.accepted` = 0, `data.rejected` = 36, `data.rejects_by_reason` =
`{"not-designatable":36}`, `data.rejects_more` = 12 (the LIST caps at 24 while
the tally stays complete — the truncation contract), and every entry of
`data.rejects`:
```json
{"at":[x,z],"why":"not-designatable","reason":"Must designate impassable mineable rocks.","removal":"none"}
```

### E2. tame on a non-animal
```json
{"id":"e2","op":"designate","args":{"type":"tame","things":[<PAWN>]}}
```
```
rwa designate --type tame --things:json '[<PAWN>]'
```
Expect `accepted:0` and one reject carrying `id` = `<PAWN>`, `def` =
`"Human"`, `why:"not-designatable"`, `reason:null`, `removal:"none"`.
`reason:null` is correct and deliberate: `Designator_Tame.CanDesignateThing`
returns a bare `false` for a humanlike, and the contract is that `reason` is
the game's own words **or nothing** — never a phrase of ours dressed up as the
game's. E3 is the same verb with a reason.

### E3. tame with a real game reason
```json
{"id":"e3a","op":"dev:spawn-pawn","args":{"kind":"Muffalo","faction":"none","pos":"<HOME>"}}
{"id":"e3b","op":"dev:add-hediff","args":{"pawn":<MUFFALO>,"def":"Scaria"}}
{"id":"e3c","op":"designate","args":{"type":"tame","things":[<MUFFALO>]}}
```
```
rwa dev:spawn-pawn --kind Muffalo --faction none --pos <HOME>
rwa dev:add-hediff --pawn <MUFFALO> --def Scaria
rwa designate --type tame --things:json '[<MUFFALO>]'
```
`<MUFFALO>` is E3a's `data.pawns[0].id`. Expect E3c: `accepted:0`, one reject
with `reason:"Scaria infected animals can't be tamed."` — the widget-layer
gate's own string, reached through `Designator_Tame.CanDesignateThing`.

### E4. deconstruct on rock — the removal taxonomy points at the right verb
Pick a natural-rock cell from A4's `map-view` (`%`) -> **`<ROCK>`**.
```json
{"id":"e4","op":"designate","args":{"type":"deconstruct","cells":["<ROCK>"]}}
```
```
rwa designate --type deconstruct --cells:json '["<ROCK>"]'
```
Expect `accepted:0` and one reject with `why:"not-designatable"` and a
`blocker` object carrying `removal:"mine"`. **That is the taxonomy earning its
keep**: the rejection names the verb that clears it. Confirm by running
`rwa designate --type mine --cells:json '["<ROCK>"]'` — `accepted:1`.

### E5. haul on something already stored
```json
{"id":"e5","op":"designate","args":{"type":"haul","rect":"<CLEARRECT>"}}
```
With the meds now inside `<MEDS>` (which overlaps `<CLEARRECT>`), expect at
least one reject with
`reason:"This is already in storage and will be moved to high-priority storage as necessary."`

### E6. fog is OUR gate, and it is stricter than the game's
Pick a cell that is still fogged — run `rwa map-view --around <HOME> --radius 30`
and take a `?` cell -> **`<FOG>`**.
```json
{"id":"e6","op":"designate","args":{"type":"mine","cells":["<FOG>"]}}
```
```
rwa designate --type mine --cells:json '["<FOG>"]'
```
Expect `accepted:0` and one reject:
```json
{"at":[x,z],"why":"fogged","reason":"unexplored","removal":"none"}
```
This is the load-bearing one. `RimWorld/Designator_Mine.CanDesignateCell`
**returns `true` for a fogged cell** — the player is allowed to paint mining
over unexplored rock. DESIGN's decisions log makes fog one rule across the
whole player-facing surface, so the engine gates it before the designator ever
runs. If this step accepts the cell, the fog invariant is broken.

### E7. zone overlap is named, not silently dropped
```json
{"id":"e7","op":"zone","args":{"op":"add","kind":"stockpile","rect":"<CLEARRECT>"}}
```
`<CLEARRECT>` is already the meds stockpile. Expect `accepted:0` and every
reject `why:"already-in-zone"`, `reason:"cell belongs to zone 'Meds 3.2' (id <MEDS>)"`.

### E8. filter beyond the five presets is refused, naming 3.6
```json
{"id":"e8","op":"zone","args":{"op":"edit","id":<MEDS>,"filter":{"def":"MedicineHerbal"}}}
```
Expect `ok:false`, `bad-args`, detail naming `spec 3.6` and
`IStoreSettingsParent`.

## F — the standing invariants

### F1. Zero red errors across the whole run
```json
{"id":"f1","op":"journal","args":{"types":["red_error","warning"],"limit":200}}
```
```
rwa journal --type red_error,warning --limit 200
```
Expect `count` = 0 for `red_error`. Warnings from other subsystems are not this
spec's, but a warning whose text starts `3.2:` is.

### F2. Every mutating call left exactly one `action` line
```json
{"id":"f2","op":"journal","args":{"types":["action"],"limit":200}}
```
```
rwa journal --type action --limit 200
```
Expect one event per mutating step above — B2, C2, C3, C9, D1a, D1b, D2, D3a,
D3b, D3c, E3c (rejections still journal: the call ran), E4's mine — each with
`payload.verb`, `payload.step`, `payload.target`, and **no `cheat` and no
`fog_exempt` field**. The `dry_run` steps (B1, B5b) must have written NOTHING.

### F3. No force-pausing window is up
```json
{"id":"f3","op":"advance","args":{"ticks":10}}
```
Expect `data.reason:"ticks"` and no `force_pause_windows` key. If `flick` had
called `FlickUtility.UpdateFlickDesignation` unmodified, D2 would have opened
`Dialog_MessageBox(SwitchFlickingDesignation)` and this step would return
`reason:"dialog"` forever after.

### F4. Clean up the fixture (optional)
```
rwa zone --op delete --id <MEDS>
rwa zone --op delete --id <RICE>
rwa designate --type cancel --rect:json '<TREERECT>'
```
`cancel` over the tree rect removes whatever chop designations remain — and
demonstrates the scoping resolution: it cancels what it is pointed at and
nothing else.

## What this script does NOT demonstrate

* Any verb running in-game — the worker compiled it and never launched the
  bench. Everything above is an expectation derived from the 1.6 decompile,
  not an observation.
* `mine-vein`, `extract-tree`, `extract-skull`, `eject-fuel`, `fill-in`,
  `deconstruct-conduit`, `release-to-wild`, `open`, `strip`, `slaughter`,
  `hunt`, `uninstall`, `smooth*`, `remove-floor`, `remove-foundation` and
  `claim` are in the table and share the one engine that B/E exercise, but no
  step stages a target for them. `claim` is the one worth a manual look if
  ancient ruins are on the map, because its `DesignateThing` acts IMMEDIATELY
  (SetFaction) rather than leaving a designation.
* `area` kinds `build-roof`, `ignore-roof`, `snow-clear`, `pollution-clear`.
* A pawn confined to an allowed area. Assignment is 3.4's verb; sequence that
  after both merge.
* Storage filter behaviour beyond the five presets — 3.6's.
